# nav

个人导航页。纯静态、无构建步骤，直接托管在 GitHub Pages。

## 文件结构

```
index.html   页面骨架 + Tailwind 运行期配置 + 少量关键 CSS
app.js       全部交互逻辑（数据规范化 / 差异引擎 / 渲染 / 编辑 / 推送）
data.json    数据文件，推送功能写入的就是它
CNAME        自定义域名
```

## 部署

把这三个文件（含 favicon）推到仓库默认分支，GitHub Pages 选择该分支根目录即可。
页面所有请求都是相对路径，放在子目录（如 `/nav/`）也能正常工作。

## 管理模式

右上角「管理」→ 输入密码。默认密码写在 `app.js` 顶部：

```js
const ADMIN_PASSWORD = 'admin123';
```

> 这是纯前端的基础鉴权，只用于防止误操作，不能替代真正的权限系统。
> 真正保护数据的是 GitHub Token —— 没有 Token 的人即使改动了页面也无法推送。

进入后可做的事：

- 分组 / 分类 / 条目的新增、删除、重命名
- 分类标签旁的「分组」下拉可直接改归属：选中即移动，移回原分组会自动插回原位置
- 变更预览、导入 / 导出 JSON、恢复线上版本
- 通过 GitHub Token 推送 data.json

## 折叠与层级

管理态下每个分组标题、分类标题左侧都有一个箭头，点标题整行即可折叠 / 展开：

- 折叠分组后只留一行标题，并补上「· N 条目」，方便判断里面有多少内容
- 折叠分类后仍保留标题行，右侧的「分组」下拉、改名、删除照常可用
- 折叠只是显示状态：不写数据、不参与差异比较，折来折去都是「无修改」
- 状态存在 `localStorage`（`nav:collapsed`），刷新后保留；数据损坏时自动退化成全展开
- 折叠状态不会影响排序模式 —— 进排序会强制全部展开（否则被隐藏元素的几何无法测量），退出后恢复

字号按四级递减，一眼能分出层级：

| 层级 | 字号 | 字重 |
| --- | --- | --- |
| 分组名 | 15px | bold |
| 分类名 | 13px | semibold |
| 条目名 | 12.5px | medium |
| 条目描述 | 10.5px | regular |

阅读态保持原样（条目名 14px），只有管理态用这套更紧凑的层级。

## 拖动排序（与增删改分离）

排序不在编辑态里，而是工具条上的「排序」按钮：

1. 点「排序」进入排序模式：所有编辑按钮消失，只留下可拖的元素，按钮变「完成」
2. 拖动**分组标题 / 分类标题 / 卡片**调整顺序（卡片整块都是拖拽区，标题左侧有六点手柄）
3. 点「完成」退出，数据立即生效；要上线仍需点「推送」

设计要点：

- 拖动期间只改数组顺序，不触发任何增删改逻辑；进出排序模式本身不会产生变更
- 指针离视口上下边缘 80px 内会自动滚页，分组区块动辄上千像素也能一次拖到位
- 移动端用 Pointer Events + `touch-action: none`，手指拖动不会被浏览器当成滚动

实现要点（`app.js` 第 6 节）：

- 激活阈值 4px，点击不会被误判成拖动
- 读写分离：`pointermove` 只记坐标，几何读取与 transform 写入合并到一帧一次
- 拖动开始时缓存「槽位表」（各元素当时的视觉位置），之后每帧只做二分查找，
  不读 DOM；因为占位元素始终占着槽位，布局在拖动过程中不变，所以不会越拖越偏
- 让位动画用 FLIP：只在索引变化时移动一次 DOM，其余元素用 transform 过渡回原位
- 定位用「右下边界」而非中心点，指针压在哪张卡片上就落在哪个槽位

## 推送配置

首次点「推送」会要求填写：

| 字段 | 说明 |
| --- | --- |
| 仓库 | `owner/repo`，也可以直接粘贴仓库地址 |
| 分支 | 一般是 `main` |
| 数据文件路径 | 默认 `data.json` |
| Token | 需要该仓库 **Contents: Read and write** 权限的 Personal Access Token |

Token 只存在本机 `localStorage`，不会发往任何第三方。推送走 GitHub Contents API
（`GET` 取 sha → `PUT` 提交），GitHub 已开放对应 CORS，因此不需要任何后端。

## 变更检测

差异比较的对象是「线上快照」与「当前工作副本」的**最终状态**，不记录操作流水。所以：

- 新增一个分类后又删掉 → 无差异
- 分类移到别的分组又移回 → 无差异（且会自动插回原位置）
- 改名后又改回来 → 无差异

新增分组 / 新增分类属于「全新子树」，里面的分类和条目会逐条列出
（新建分类后往里加条目，预览里能看到每一条；分类被移组后新增的条目同样会报出来）。
删除仍保持汇总，例如「删除分类「X」（含 12 个条目）」，避免一次删掉整组时刷屏。

实现上分三级对齐：先按 id 精确匹配，再按名称兜底，条目最后再按链接兜底
（所以只改名字不会被误报成「删除 + 新增」）。顺序变化用 LIS（最长递增子序列）求最小移动集，
因此「两项互换」只会报 1 处排序变化，而不是 2 处。单次 diff 约 0.1ms。

## 数据格式

当前为 v2：

```json
{
  "version": 2,
  "title": "PasserJ's Nav",
  "groups": [
    {
      "id": "g1",
      "name": "工具",
      "categories": [
        { "id": "c1", "name": "常用工具", "items": [{ "name": "kimi", "url": "https://www.kimi.com", "desc": "" }] }
      ]
    }
  ]
}
```

导入时兼容旧格式 `{ "project1": [{ "category": "...", "items": [...] }] }`，会自动转换。
`id` 用于差异比对，手工编辑时保持唯一即可。
